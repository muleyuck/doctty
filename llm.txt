# doctty — context for LLMs and coding agents

This file summarizes how end users install and run `doctty` (Markdown viewer for Ghostty and Kitty).
Authoritative details: README.md for user-facing behavior, AGENTS.md for development guidance, and source code/tests for implementation contracts.

## What it is

- Binary name: doctty
- Renders GitHub Flavored Markdown (GFM) in the terminal with rich layout, images, code highlighting, optional Mermaid.
- Interactive mode: requires Ghostty or Kitty (terminal detection).
- If stdout is not a TTY (pipe, redirect, CI), doctty prints plain text to stdout instead of opening the interactive viewer.

## Installation (from source)

Clone this repository and run `cargo install --path . --locked` (Rust 1.92+).
For local development use `make build`, then `./bin/doctty README.md`.
Versioned GitHub Releases and Homebrew distribution are planned. There is no installer script or self-update subcommand.

## Basic usage

  doctty <PATH_TO_MARKDOWN_FILE>

Examples:

  doctty README.md
  doctty --theme dark --watch ./examples/rich_markdown.md
  doctty --no-mermaid notes.md
  doctty --version
  doctty --help

## CLI flags (clap / DocttyArgs)

- path: required positional argument — Markdown file to open (PathBuf).
- --watch: reload when the file changes on disk.
- --theme <system|light|dark>: default is system.
- --no-mermaid: disable Mermaid rendering; show placeholders.

## Environment variables (common)

- DOCTTY_MERMAID_CMD: optional explicit command for Mermaid CLI; otherwise mmdc or npx @mermaid-js/mermaid-cli may be used.

## Troubleshooting (short)

- command not found: ensure Cargo's bin directory (usually ~/.cargo/bin) is on PATH.
- unsupported terminal in interactive mode: use Ghostty or Kitty.
- plain text instead of viewer: stdin/stdout not both a TTY (expected for scripts).
- Mermaid missing: install Mermaid CLI or set DOCTTY_MERMAID_CMD; or use --no-mermaid.
